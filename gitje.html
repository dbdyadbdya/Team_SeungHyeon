0. 제일 먼저 이해할 것

Git은 내 컴퓨터에서 변경 기록을 관리하고, GitHub는 그 기록을 인터넷에서 팀원과 공유하는 공간이다.

① 파일 수정VS Code
② git add올릴 변경 선택
③ git commit변경 저장
④ git pull최신 작업 받기
⑤ git pushGitHub에 올리기
핵심 습관: 작업 시작 전 git pull, 작업 후 git add → git commit → git pull → git push.

1. 처음 프로젝트 받을 때 — 딱 한 번

① GitHub 저장소 주소 복사

팀 저장소에서 Code → HTTPS 주소 복사.

② 프로젝트를 둘 폴더로 이동

cd Desktop

③ 저장소 복제

git clone https://github.com/팀계정/DATA-TIP-OFF.git

clone은 처음 한 번만 사용.

④ 프로젝트 폴더로 이동

cd DATA-TIP-OFF

⑤ VS Code로 열기

code .
중요: 이미 프로젝트 폴더가 있으면 다시 clone하지 말고, 그 폴더에서 git pull을 사용한다.

2. ⭐ 매일 작업할 때 가장 중요한 순서

작업 시작

git status
git pull origin main

VS Code에서 파일 수정 후

git status
git add .
git commit -m "경제 Signal 분석 추가"
git pull origin main
git push origin main

왜 push 직전에 pull?

내가 작업하는 동안 팀원이 먼저 push했을 수 있기 때문이다. 최신 작업을 먼저 받은 뒤 내 작업과 합치고 올리는 게 안전하다.

4. 상황별로 지금 뭘 입력해야 하지?

상황 A — 오늘 처음 작업 시작
cd 프로젝트폴더 git status git pull origin main
상황 B — 새 HTML 파일 생성 후 업로드
git status git add . git commit -m "메인 페이지 HTML 추가" git pull origin main git push origin main
상황 C — 기존 style.css만 수정
git diff git add static/css/style.css git commit -m "메인 카드 스타일 수정" git pull origin main git push origin main
상황 D — 팀원이 방금 올렸다고 함
git pull origin main
상황 E — 수정했지만 아직 GitHub에는 안 올리고 싶음
git add . git commit -m "K-Contents API 1차 테스트"

commit까지만 하면 내 PC 기록에만 저장. push해야 GitHub에 올라간다.

상황 F — 내가 뭘 수정했는지 모르겠음
git status git diff

5. 팀 프로젝트에서는 브랜치를 쓰면 더 안전함

세 명이 모두 main에 바로 push할 수 있지만, 같은 파일을 같이 수정하면 충돌이 난다. 초보 팀은 개인/기능 브랜치 → 작업 → push → Pull Request → main에 merge가 안전하다.

① 작업 브랜치 생성

git switch -c feature/economy

예: feature/economy, feature/kcontents, feature/sports, feature/front

② 현재 브랜치 확인

git branch

③ 작업 후 내 브랜치에 업로드

git add . git commit -m "아파트 Signal 분석 추가" git push origin feature/economy

④ GitHub에서 Pull Request 생성

내 브랜치를 main에 합쳐달라는 요청을 만들고, 확인 후 Merge.

⑤ 최신 main 받기

git switch main git pull origin main
추천 규칙: 같은 style.css나 app.py를 동시에 수정하지 않도록 팀 채팅에 “지금 이 파일 수정 중”이라고 알린다.

6. 충돌(CONFLICT)이 났을 때

내 코드와 팀원 코드가 같은 부분을 서로 다르게 수정하면 Git이 자동으로 합치지 못할 수 있다.

<<<<<<< HEAD
내 코드
=======
팀원 코드
>>>>>>>

VS Code에서 원하는 코드만 남기고 충돌 표시를 지운 뒤 저장한다.

git add . git commit -m "프론트 충돌 해결" git push origin main
주의: 충돌이 났다고 팀원 코드를 무조건 지우지 말고, 필요한 코드를 직접 합친다.

7. 잘못했을 때 유용한 안전 명령어

git add 취소

git restore --staged 파일명

commit 전 파일 수정 내용 완전 취소

git restore 파일명
주의: 수정 내용이 실제로 사라질 수 있으니 정말 버려도 될 때만 사용.

최근 commit 확인

git log --oneline -10

12. 헷갈리는 개념 한 줄 정리

clone프로젝트를 처음 통째로 받기
pull이미 받은 프로젝트에서 최신 변경분 받기
add이번에 저장할 변경 파일 선택
commit변경 내용을 Git 기록으로 저장
push내 commit을 GitHub에 업로드
branchmain을 건드리지 않고 별도 작업 공간 만들기
merge서로 다른 브랜치의 작업 합치기
conflict같은 부분을 서로 다르게 수정해 자동 병합이 안 되는 상태
